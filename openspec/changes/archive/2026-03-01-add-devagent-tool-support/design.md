## Context

OpenSpec maintains a single array `AI_TOOLS` in `src/core/config.ts`. Each entry has `name`, `value`, `available`, optional `successLabel`, and optional `skillsDir`. Init and update use `getToolsWithSkillsDir()` (values of tools that have `skillsDir`) to drive the "Select tools" multi-select and to validate `--tools`. Tool detection scans the project for directories matching each tool's `skillsDir` (e.g. `.cursor`). Adding a new tool is therefore a single-point change: one new row in `AI_TOOLS` with a consistent `skillsDir` convention.

DevAgent is an AI coding assistant that is not currently in the list. No new subsystems or adapters are required for minimal support: skills and commands are generated by the same pipeline (skill templates + command adapters). If DevAgent uses the same command file format as an existing tool (e.g. Cursor), we can reuse that adapter; otherwise we use a generic or Cursor-like adapter until a DevAgent-specific adapter is added later.

## Goals / Non-Goals

**Goals:**

- DevAgent appears in the init/update "Select tools" list and can be selected interactively or via `--tools devagent`.
- Skills are written to `<projectRoot>/.devagent/skills/` and commands to `<projectRoot>/.devagent/commands/` (or the path dictated by DevAgent docs if different).
- Existing behavior (detection, validation, success messages) applies to DevAgent without special cases.
- One source of truth: only `config.ts` is extended; no new detection or config files.

**Non-Goals:**

- DevAgent-specific slash-command frontmatter or command adapter (can be a follow-up).
- Auto-detection of "DevAgent installed" beyond the existing mechanism (presence of `.devagent` directory).
- Documentation or marketing copy beyond what is needed for the change.

## Decisions

1. **Add one entry to `AI_TOOLS`**
   - **Choice**: Add `{ name: 'DevAgent', value: 'devagent', available: true, successLabel: 'DevAgent', skillsDir: '.devagent' }` in alphabetical order by display name (e.g. after "Crush", before "Factory Droid").
   - **Rationale**: Matches all other tools; `getToolsWithSkillsDir()`, `getAvailableTools()`, init, and update already consume `AI_TOOLS`. No new code paths.
   - **Alternative**: External config file for tools. Rejected to avoid fragmentation and to keep the list in one place.

2. **Use `skillsDir: '.devagent'`**
   - **Choice**: Use `.devagent` as the project-local base directory (skills under `.devagent/skills/`, commands under `.devagent/commands/`).
   - **Rationale**: Convention matches `.cursor`, `.claude`, etc. If DevAgent’s official docs specify a different path, we can change it in a follow-up.
   - **Alternative**: Research DevAgent’s exact directory. Deferred; we can align later if needed.

3. **Command generation for DevAgent**
   - **Choice**: Do not add a dedicated DevAgent command adapter in this change. Use the existing adapter registry; if DevAgent matches Cursor’s format, register it to use the Cursor adapter (optional follow-up), otherwise skills-only or a generic adapter is sufficient for "select and configure" to work.
   - **Rationale**: Proposal scope is "support selecting DevAgent"; generation already works for any tool with `skillsDir`. Adapter can be added when we know DevAgent’s command format.

## Risks / Trade-offs

- **[Risk]** DevAgent may use a different directory (e.g. `.devagent-cli`). **[Mitigation]** Use `.devagent` by default; document or change in a patch if users report mismatch.
- **[Risk]** Tests that assert on the exact count or list of tools may break. **[Mitigation]** Update tests that depend on tool count or tool IDs (e.g. available-tools, init, update) to include `devagent` where appropriate.

## Migration Plan

- No migration. New entry is additive; existing configs and projects unchanged.
- Rollback: remove the DevAgent entry from `AI_TOOLS` and revert spec/test changes.

## Open Questions

- None. DevAgent’s exact command/skill path convention can be confirmed later and adjusted in config if needed.
